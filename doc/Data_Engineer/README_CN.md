# 数据工程师 — 职责与分级交付要求

[English](README.md) · [简体中文](README_CN.md) · [项目总览](../../README_CN.md)

> **项目:** Datathon 用例 4 — AI 辅助传统系统迁移  
> **技术栈：** Python + SQL + Amazon S3 + Snowflake + Streamlit（无强制 Java／Spring Boot／独立 API）。  
> **状态：** 以下是任务与验收标准，不代表功能已实现。

## 1. 角色职责与边界

**核心职责：** 通过 Python 和 S3 将已确认的源数据快照导入 Snowflake RAW，并确保批次可追溯、重跑安全。

**职责边界：** 负责数据提取、格式检查、导入及批次元数据；不得为强行通过对账而暗改 KPI 计算或无记录地丢弃异常源数据。

## 2. 技能等级与任务规则

**Minimum** 为本角色的 MVP 必交项，适合在指导下完成明确任务的成员；**Standard** 包含 Minimum，适合能独立实施与测试的成员；**Advanced** 包含前两级，适合承担复杂故障、自动化与架构增强的成员。能力等级用于分配任务，不是人员评价。

### 最低交付（Minimum Delivery）

**适配经验：** 能使用 Python 检查／导出数据，并按文档执行基础 Snowflake 导入。

**本项目任务：**

- 检查真实的源工作表／表，记录源行数、字段、类型与异常，不预先假设列名。
- 使用 Python 将一份已确认数据导出为 CSV／Parquet，保存不变的源快照和简单批次清单到 S3。
- 经配置的 Stage 与 `COPY INTO` 创建／导入一张 Snowflake RAW 表，记录导入结果及被拒绝或缺失的行。
- 重跑前确认相同文件／批次是否已经导入，避免直接重复追加。

**具体交付物：**

- `src/extract.py`、`src/ingest.py`（或同等可复现脚本）及 `sql/raw/` 导入定义。
- 源与 RAW 行数核对、源路径／哈希及基本批次／导入日志。

**验收标准：**

- 一份源文件通过 S3 成功进入 RAW，团队能复现导入。
- 任何源／导入行数差异均有解释；简单重跑不会使正式业务指标翻倍。

### 标准交付（Standard Delivery）

**适配经验：** 能建立可重复执行的导入管道，区分数据问题与暂时的基础设施故障。

**本项目任务：**

- 分配 `batch_id` 与唯一 `run_id`，记录文件哈希、S3 Key、时间、状态、预期／导入／拒绝行数与错误类别。
- 实现并测试相同批次的幂等重跑策略，例如结合加载历史与明确的按批次替换／合并规则。
- 仅对暂时网络／上传故障进行有限退避重试，将错误格式文件／记录隔离以供检查。
- 向验证与发布环节传递一致的导入状态／元数据；不能仅因 RAW 导入成功就标记为 PUBLISHED。

**具体交付物：**

- `src/pipeline.py` 导入阶段和可审计的批次清单／运行日志表或等效存储。
- 相同批次重跑及一次模拟暂时故障／数据错误的测试证据。

**验收标准：**

- 同一源批次执行两次，不产生额外业务记录。
- 格式错误文件被记录为失败／拒绝，不会静默通过；暂时故障的重试次数有上限。

### 进阶交付（Advanced Delivery）

**适配经验：** 能实现感知变更的增量导入，并从部分执行失败的管道中安全恢复。

**本项目任务：**

- 仅当源数据支持时，利用稳定源键、Watermark／变更标识及明确的迟到数据策略实现增量导入。
- 设置阶段级检查点，使中断运行可恢复且不覆盖上一正式 MART。
- 增加自动调度、重复失败监控／告警，以及 Schema 演进与批次重放测试。

**具体交付物：**

- 增量／恢复操作手册及自动化管道配置。
- 批次重放、部分失败恢复及 Schema 变化处理的验证证据。

**验收标准：**

- 中断或重复的批次可以恢复，且不会造成正式结果重复。
- 增量行为及迟到数据限制依据真实存在的源字段说明并经过测试。

## 3. 跨角色输入与交接

**需要从其他角色获取：**

- 由 Data Analyst 与 Solution Architect 确认的源文件／表及字段。
- Cloud Engineer 提供的 S3 路径、External Stage、DEV 凭证与权限。

**需要向其他角色交付：**

- RAW 表／Schema、源文件 ID、批次／运行 ID、源／导入行数和错误 → Analytics Engineer 与 Data Scientist。
- 安全重跑说明与导入证据 → Solution Architect。

## 4. 全团队共同遵守的验收约束

- 原始数据、运行批次及转换过程必须可追溯；不允许无记录地删除异常行。
- 仅候选 MART 通过独立对账与关键质量检查后，才允许更新正式查询入口；失败批次不能替换上一成功版本。
- AI 生成的 SQL 必须经人工审核并在 DEV／候选数据测试；验证基准不得仅由同一 AI 生成。
- Streamlit 只读已发布数据；如果尚无成功版本，应明确显示“暂无已验证数据”。
- 不得将计划、未执行的测试或可选 Advanced 功能标注为已完成。
