# 解决方案架构师／团队负责人 — 职责与分级交付要求

[English](README.md) · [简体中文](README_CN.md) · [项目总览](../../README_CN.md)

> **项目:** Datathon 用例 4 — AI 辅助传统系统迁移  
> **技术栈：** Python + SQL + Amazon S3 + Snowflake + Streamlit（无强制 Java／Spring Boot／独立 API）。  
> **状态：** 以下是任务与验收标准，不代表功能已实现。

## 1. 角色职责与边界

**核心职责：** 负责端到端迁移的范围、架构、具名分工、跨模块集成及基于验证证据的发布决策。

**职责边界：** 负责协调而非默认编写所有模块。Data Analyst 负责业务口径，Data Scientist 负责独立验证；必须指定具备 Python 能力的 Streamlit 开发负责人。Java 和独立 REST API 不再是必选项。

## 2. 技能等级与任务规则

**Minimum** 为本角色的 MVP 必交项，适合在指导下完成明确任务的成员；**Standard** 包含 Minimum，适合能独立实施与测试的成员；**Advanced** 包含前两级，适合承担复杂故障、自动化与架构增强的成员。能力等级用于分配任务，不是人员评价。

### 最低交付（Minimum Delivery）

**适配经验：** 能解释基础数据流，协调有依赖关系的任务，区分拟议功能与实际完成证据。

**本项目任务：**

- 确认一份源数据、可用的旧 SQL／报表逻辑及一个按地区统计的月销售额 KPI；未知字段必须标注，不能虚构。
- 绘制 Python → S3 → Snowflake RAW／STAGING／候选 MART → 验证关卡 → 正式 MART → Streamlit 数据流，并标注 AI 审核与独立基准。
- 为 AWS、导入、建模、KPI、独立验证、Streamlit 编码及发布批准指定具体负责人。
- 约定首个 MART 查询的字段与筛选、最低验收清单及一条端到端演示路径。

**具体交付物：**

- `docs/architecture.md`：架构图、MVP 边界、假设及 Python／SQL 选型原因。
- `docs/ownership.md` 与 `docs/acceptance.md`：负责人、交接、验收及证据链接。

**验收标准：**

- 每项必需任务与 Streamlit 实现均有负责人，Java／独立 API 不再被误列为必交。
- 评审者能追踪源 KPI 经数据导入、SQL、验证直至正式 Dashboard 展示的全过程。

### 标准交付（Standard Delivery）

**适配经验：** 能定义跨模块契约，并设计贯穿迁移各阶段的安全故障处理。

**本项目任务：**

- 明确源文件标识、批次与运行 ID、Schema、业务粒度、预期输出及各阶段交接格式。
- 设计运行状态、有限重试、幂等重跑、候选与正式数据隔离，以及人工或自动发布批准流程。
- 规定最小权限、密钥管理、成本责任人及 Streamlit 对正式数据的只读访问。
- 组织一次成功发布与一次 KPI 检查失败的集成测试，确保失败时正式数据不被替换。

**具体交付物：**

- `docs/data-contracts.md` 与 `docs/integration-test-plan.md`，明确字段、筛选与故障语义。
- 运行状态／发布设计、风险清单及集成测试证据。

**验收标准：**

- 团队可按书面契约开发，无需猜测质量检查或发布由谁负责。
- 故意制造的失败候选批次不会发布；上一成功结果仍可访问，若从未成功则 UI 明确提示。

### 进阶交付（Advanced Delivery）

**适配经验：** 能设计可恢复架构、论证工程取舍并建立可复现迁移治理。

**本项目任务：**

- 设计版本化发布、原子读取入口切换或等效受控指针，并演练错误发布的回滚。
- 针对源 Schema 漂移、重复批次、导入中断和 KPI 口径冲突开展故障演练，明确事故负责人。
- 记录受控 AI 转换流程，要求 SQL 经人工审核、仅在 DEV 执行并接受独立验收。
- 编写可复用迁移手册，并注明可测量的工时、成本假设及已知限制。

**具体交付物：**

- `docs/migration-playbook.md`、发布／回滚清单和故障演练证据。
- 记录成本、安全、AI 批准与剩余风险的架构决策日志。

**验收标准：**

- 错误发布版本能够回滚，且不会暗中改写独立基准。
- 其他成员可按文档重现恢复过程，并说明哪些步骤仍需人工操作。

## 3. 跨角色输入与交接

**需要从其他角色获取：**

- 比赛要求、已核实的源文件及可用的原始报表逻辑。
- 团队能力与投入时间、云权限，以及分析师提出的独立基准。

**需要向其他角色交付：**

- 已确认的架构图、职责与安全边界 → 全体成员。
- 数据契约、发布规则与演示验收标准 → 导入、SQL、验证及 Streamlit 负责人。

## 4. 全团队共同遵守的验收约束

- 原始数据、运行批次及转换过程必须可追溯；不允许无记录地删除异常行。
- 仅候选 MART 通过独立对账与关键质量检查后，才允许更新正式查询入口；失败批次不能替换上一成功版本。
- AI 生成的 SQL 必须经人工审核并在 DEV／候选数据测试；验证基准不得仅由同一 AI 生成。
- Streamlit 只读已发布数据；如果尚无成功版本，应明确显示“暂无已验证数据”。
- 不得将计划、未执行的测试或可选 Advanced 功能标注为已完成。
