# 数据分析师 — 职责与分级交付要求

[English](README.md) · [简体中文](README_CN.md) · [项目总览](../../README_CN.md)

> **项目:** Datathon 用例 4 — AI 辅助传统系统迁移  
> **技术栈：** Python + SQL + Amazon S3 + Snowflake + Streamlit（无强制 Java／Spring Boot／独立 API）。  
> **状态：** 以下是任务与验收标准，不代表功能已实现。

## 1. 角色职责与边界

**核心职责：** 定义迁移报表的业务含义，独立计算旧系统基准，并设计或实现清晰的 Streamlit 看板。

**职责边界：** 负责 KPI 口径和业务签核。Streamlit 编码必须指定具名负责人：如果分析师会 Python，可以由其承担；只有草图不算可运行界面。独立技术对账由 Data Scientist 负责。

## 2. 技能等级与任务规则

**Minimum** 为本角色的 MVP 必交项，适合在指导下完成明确任务的成员；**Standard** 包含 Minimum，适合能独立实施与测试的成员；**Advanced** 包含前两级，适合承担复杂故障、自动化与架构增强的成员。能力等级用于分配任务，不是人员评价。

### 最低交付（Minimum Delivery）

**适配经验：** 能检查实际源数据、定义一个可复现 KPI 并设计基础用户报表。

**本项目任务：**

- 检查真实源字段，定义销售额、报表月份／时区、地区、币种、退货及缺失值处理，不虚构源数据没有的属性。
- 独立于 Snowflake 候选 MART 计算并保存源／旧系统 KPI 基准。
- 设计 Streamlit 的一张 KPI 卡、月份／地区筛选、一张图、刷新时间及可见的发布批次／验证状态。
- 与 Team Lead 确认由谁编码 Streamlit，并交付所需正式 MART 字段与展示语义。

**具体交付物：**

- `docs/data-dictionary.md` 与 `docs/legacy-baseline.md`：来源、公式、假设与基准值。
- `docs/dashboard-spec.md` 或等效草图，注明 Streamlit 开发负责人和验收用例。

**验收标准：**

- 其他成员可按指定源数据及日期／币种／退货规则复算基准。
- 具名 UI 开发者无需猜测字段、KPI 含义或可展示的数据状态即可实现基础看板。

### 标准交付（Standard Delivery）

**适配经验：** 能把业务规则转为可复现分析，并实现或测试可靠的 Streamlit 体验。

**本项目任务：**

- 扩展 KPI 的可用维度、退货分类、时间边界和排除规则，维护版本化基准。
- 与具名 Streamlit 负责人实现筛选、图表标签、无数据／加载／错误状态，并区分当前正式版本与最近失败运行。
- 按月份和地区对比新旧报表，编写退货、地区缺失及零销售月份的业务验收用例。
- 确保 Streamlit 只读正式 MART，不将候选或失败批次指标当作已验证 KPI 展示。

**具体交付物：**

- 版本化 KPI 字典及新旧报表并排对比。
- 已测试的 Streamlit MVP（若由本人编码）或对具名开发者成果签核的 UI 测试记录。

**验收标准：**

- 相同业务口径下，筛选与展示同 KPI 基准及正式 MART 一致。
- UI 如实标注过期／失败／空状态，不暗中以最新未验证候选结果替换。

### 进阶交付（Advanced Delivery）

**适配经验：** 能设计面向业务的迁移就绪报告并评估数据差异影响。

**本项目任务：**

- 围绕真实可用维度设计下钻、验证趋势、最近成功批次及未解决异常数量。
- 将业务重大性阈值与不可妥协的技术完整性关卡分开，记录任何 KPI 口径变更的批准。
- 组织业务方评审报表已知限制、刷新服务目标以及回退上一验证版本／旧报表的方式。

**具体交付物：**

- 迁移就绪看板或规格及业务方评审证据。
- 指标变更日志、差异影响说明及数据新鲜度／验收策略。

**验收标准：**

- 用户能区分通过、阻断和过期数据，未解决差异不会被隐藏。
- 业务口径变化需要版本化签核，不能追溯性暗改独立基准。

## 3. 跨角色输入与交接

**需要从其他角色获取：**

- 真实源字段、旧报表及业务背景。
- Analytics Engineer、Data Scientist 与 Architect 提供的正式 MART 查询入口及验证状态。

**需要向其他角色交付：**

- KPI 字典与独立基准 → Analytics Engineer 和 Data Scientist。
- Streamlit 规格、所需字段／筛选和业务验收 → 具名 UI 负责人及 Architect。

## 4. 全团队共同遵守的验收约束

- 原始数据、运行批次及转换过程必须可追溯；不允许无记录地删除异常行。
- 仅候选 MART 通过独立对账与关键质量检查后，才允许更新正式查询入口；失败批次不能替换上一成功版本。
- AI 生成的 SQL 必须经人工审核并在 DEV／候选数据测试；验证基准不得仅由同一 AI 生成。
- Streamlit 只读已发布数据；如果尚无成功版本，应明确显示“暂无已验证数据”。
- 不得将计划、未执行的测试或可选 Advanced 功能标注为已完成。
