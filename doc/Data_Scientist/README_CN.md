# 数据科学家 — 职责与分级交付要求

[English](README.md) · [简体中文](README_CN.md) · [项目总览](../../README_CN.md)

> **项目:** Datathon 用例 4 — AI 辅助传统系统迁移  
> **技术栈：** Python + SQL + Amazon S3 + Snowflake + Streamlit（无强制 Java／Spring Boot／独立 API）。  
> **状态：** 以下是任务与验收标准，不代表功能已实现。

## 1. 角色职责与边界

**核心职责：** 独立评估输入数据质量，对账源数据与候选结果，并提供验证关卡使用的证据。

**职责边界：** 负责独立数据检查和差异分析，不负责擅自重定义 KPI 或偷偷修改导入；机器学习是可选增强，不是正确迁移的前置条件。

## 2. 技能等级与任务规则

**Minimum** 为本角色的 MVP 必交项，适合在指导下完成明确任务的成员；**Standard** 包含 Minimum，适合能独立实施与测试的成员；**Advanced** 包含前两级，适合承担复杂故障、自动化与架构增强的成员。能力等级用于分配任务，不是人员评价。

### 最低交付（Minimum Delivery）

**适配经验：** 能独立完成数据概况检查，并对比源记录和一个已定义 KPI。

**本项目任务：**

- 检查缺失、候选键重复、异常类型、非法日期／金额和源文件完整性；不能默认将正常退货视为异常。
- 比较原始源行数和 RAW 导入行数，记录有意拒绝的记录及剩余差异。
- 依据分析师确认的源业务口径独立复算一个月度销售 KPI，并与候选 MART 比较。
- 记录通过／失败及原因，将无法解释的关键差异上报 Architect，不得标记为成功。

**具体交付物：**

- `docs/data-quality-report.md`：字段级问题、来源和数量。
- `docs/validation-report.md`：源／RAW 行数、一个 KPI 对比及明确判定。

**验收标准：**

- 其他成员能够依据文档中的公式及来源复现源行数和选定 KPI。
- 关键行数／KPI 差异在依据明确规则解释并签核前不得批准发布。

### 标准交付（Standard Delivery）

**适配经验：** 能自动化独立分组对账并设计有意义的数据质量关卡。

**本项目任务：**

- 编写独立于 AI 转换代码的 Python／SQL 测试，检查必填、唯一性、日期／金额及源目标总量。
- 按月份 × 地区及可用的产品类别比较，找出被相同总额掩盖的抵消误差。
- 将差异分为源数据缺陷、映射／聚合错误、导入问题或业务口径差异，并指定处理负责人。
- 向验证关卡输出机器可读的通过／失败结果，并测试失败候选批次不能发布。

**具体交付物：**

- `src/validate.py` 和／或 `sql/tests/`，实现可重复的总体及分组对账。
- 差异登记表及一次阻断发布的测试记录。

**验收标准：**

- 即使总销售额不变，独立检查仍能发现人为植入的月份／地区错配。
- 只有真实通过的检查才标记通过，失败可追溯至批次与数据源。

### 进阶交付（Advanced Delivery）

**适配经验：** 能跨多个运行评估模型／转换质量并识别源数据行为变化。

**本项目任务：**

- 在固定、明确列出的转换集合上测量 AI SQL 首次等价率，注明样本量、测试维度及不确定性。
- 设计参考数据漂移及 Schema／质量异常检查，设置合适阈值并复核误报。
- 开展故障／错误 SQL 实验，证明无效批次被隔离而先前发布的 KPI 仍可展示。
- 仅在实际字段支持有意义评估时，选择展示需求预测或临期预警。

**具体交付物：**

- 有明确范围的 AI 评估及漂移／故障测试证据。
- 已记录的异常复核与可选 ML 实验及其限制。

**验收标准：**

- 转换准确性主张明确列出评估案例及分母，并使用独立基准。
- 故障注入证据证明无效发布被阻断，且未追溯性修改源 KPI 规则。

## 3. 跨角色输入与交接

**需要从其他角色获取：**

- Data Engineer 提供的原始快照、源行数与 RAW 批次记录。
- Data Analyst 提供的已确认 KPI 基准；Analytics Engineer 提供的候选 MART SQL／结果和 AI 日志。

**需要向其他角色交付：**

- 通过／失败检查、差异明细和独立对账 → Architect 及 SQL／数据负责人。
- 批准的验证状态和明确的限制 → 经发布关卡传递给 Streamlit 负责人。

## 4. 全团队共同遵守的验收约束

- 原始数据、运行批次及转换过程必须可追溯；不允许无记录地删除异常行。
- 仅候选 MART 通过独立对账与关键质量检查后，才允许更新正式查询入口；失败批次不能替换上一成功版本。
- AI 生成的 SQL 必须经人工审核并在 DEV／候选数据测试；验证基准不得仅由同一 AI 生成。
- Streamlit 只读已发布数据；如果尚无成功版本，应明确显示“暂无已验证数据”。
- 不得将计划、未执行的测试或可选 Advanced 功能标注为已完成。
