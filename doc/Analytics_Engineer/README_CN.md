# 分析工程师 — 职责与分级交付要求

[English](README.md) · [简体中文](README_CN.md) · [项目总览](../../README_CN.md)

> **项目:** Datathon 用例 4 — AI 辅助传统系统迁移  
> **技术栈：** Python + SQL + Amazon S3 + Snowflake + Streamlit（无强制 Java／Spring Boot／独立 API）。  
> **状态：** 以下是任务与验收标准，不代表功能已实现。

## 1. 角色职责与边界

**核心职责：** 使用 AI 辅助转换真实旧报表逻辑，构建透明、可测试的 Snowflake STAGING 与候选 MART 模型。

**职责边界：** 负责 SQL 语义、数据转换和 AI 转换记录；业务定义由 Data Analyst 确认，目标结果由 Data Scientist 独立验证。不得对正式数据执行未经审核的 AI SQL。

## 2. 技能等级与任务规则

**Minimum** 为本角色的 MVP 必交项，适合在指导下完成明确任务的成员；**Standard** 包含 Minimum，适合能独立实施与测试的成员；**Advanced** 包含前两级，适合承担复杂故障、自动化与架构增强的成员。能力等级用于分配任务，不是人员评价。

### 最低交付（Minimum Delivery）

**适配经验：** 能读懂源查询／报表定义，在 DEV 中调整 SQL 并解释所得 KPI 的业务粒度。

**本项目任务：**

- 梳理至少一段真实旧查询或原始报表转换逻辑；若不存在旧 SQL，须明确说明，不能虚构。
- 使用 AI 起草等价 Snowflake 查询；人工检查关联、NULL、日期、币种、退货和分组。
- 建立一条 STAGING 转换及独立候选 MART，计算约定的按地区月销售额 KPI，并保留 RAW。
- 向 Data Scientist 交接前，记录原始逻辑、AI 提示词／输出、人工修改及测试结果。

**具体交付物：**

- `sql/legacy/`、`sql/staging/`、`sql/mart/` 及 `docs/source-to-target.md`。
- `docs/ai-conversion-log.md`，包含经人工审核的转换样例及候选 KPI 查询。

**验收标准：**

- 已审核 SQL 可在 DEV／候选数据执行，且 KPI 符合记录的源业务口径。
- 转换记录区分真实旧 SQL 与重建的报表逻辑，不将未经验证的结果宣称为等价。

### 标准交付（Standard Delivery）

**适配经验：** 能独立维护可复用分析模型并发现常见 SQL 转换错误。

**本项目任务：**

- 记录源到目标的类型、键、业务粒度映射，以及每项记录过滤／修改规则。
- 加入业务粒度唯一、关键字段非空、值域、关联和聚合不变量的可执行测试；dbt 按需使用。
- 支持月份 × 地区层面的独立对账，解决发现的差异或明确记录。
- 保持候选转换与正式对象隔离，仅在必要检查通过且有批准记录后升级。

**具体交付物：**

- 带测试与版本的 STAGING／MART SQL、映射字典及测试结果日志。
- 扩展的 AI 转换／审核记录及分组 KPI 对账支持。

**验收标准：**

- 关键测试通过或产生明确阻断状态，不能用静默过滤掩盖差异。
- Data Scientist 能依据 SQL 与映射文档独立复算月度／地区候选指标。

### 进阶交付（Advanced Delivery）

**适配经验：** 能设计受治理的 SQL 发布流程并评估可复现的 AI 转换工作流。

**本项目任务：**

- 识别上游 Schema／粒度变化，保留源到 MART 血缘并记录受影响指标。
- 试作 SQL／测试建议助手，但必须人工批准且仅在 DEV 执行被接受的语句。
- 对明确列出的真实转换集合测量首次正确率和审核工时，并标明分母。
- 记录 SQL／模型回滚与发布兼容性检查。

**具体交付物：**

- 数据血缘及兼容性检查、受控 AI 转换原型或可复现工作流。
- 注明范围的 AI 评估及模型发布／回滚证据。

**验收标准：**

- 不能仅因 AI SQL 可执行就发布；必须经过源 KPI 对账及批准。
- 评估指标、血缘和回滚步骤能由留存证据复现。

## 3. 跨角色输入与交接

**需要从其他角色获取：**

- Data Engineer 提供的 RAW Schema、批次与来源元数据。
- Data Analyst 提供的原始报表／SQL、KPI 公式及独立基准。

**需要向其他角色交付：**

- 已审核 SQL、字段映射、STAGING 与候选 MART → Data Scientist；发布后供 Streamlit 负责人使用。
- 转换测试、AI 提示词／修改记录及差异说明 → Solution Architect。

## 4. 全团队共同遵守的验收约束

- 原始数据、运行批次及转换过程必须可追溯；不允许无记录地删除异常行。
- 仅候选 MART 通过独立对账与关键质量检查后，才允许更新正式查询入口；失败批次不能替换上一成功版本。
- AI 生成的 SQL 必须经人工审核并在 DEV／候选数据测试；验证基准不得仅由同一 AI 生成。
- Streamlit 只读已发布数据；如果尚无成功版本，应明确显示“暂无已验证数据”。
- 不得将计划、未执行的测试或可选 Advanced 功能标注为已完成。
